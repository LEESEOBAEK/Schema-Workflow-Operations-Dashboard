# Portfolio Growth Log

GitHub 공개 활동의 반응을 주 단위로 기록하는 소유자용 양식입니다. 숫자는 저장소의 `Insights > Traffic`과 `Releases`에서 확인하며, 공개 성과를 과장하지 않고 같은 기준으로 비교합니다.

## 확인 대상

| 저장소 | 역할 | 대표 지표 |
|---|---|---|
| Schema Workflow Operations Dashboard | 대표 제품 | 고유 방문자, README 인기 경로, Star |
| Workflow Input Assistant | 진입 도구 | 고유 방문자, Release 다운로드, Star |
| Schema Workflow Showcase | 결과 증명 | 고유 방문자, 사례 페이지 조회, 유입 경로 |

## 주간 기록

| 기준일 | 저장소 | Views | Unique visitors | Clones | Unique cloners | Stars | Release downloads | 주요 유입 경로 | 메모 |
|---|---|---:|---:|---:|---:|---:|---:|---|---|
| YYYY-MM-DD | 저장소명 | 0 | 0 | 0 | 0 | 0 | 0 | - | 변경·공유 활동 기록 |

## 해석 규칙

- 하루 수치보다 최근 2주 추세를 봅니다.
- Views가 늘고 Unique visitors가 그대로면 같은 방문자의 재방문일 수 있습니다.
- Unique visitors가 늘고 README의 빠른 실행 구간이 많이 읽히면 소개 문구가 유입에 기여한 것으로 봅니다.
- 방문은 늘지만 Star와 다운로드가 늘지 않으면 설치 방법, 데모, 가치 설명을 먼저 개선합니다.
- 외부 공유 직후에는 유입 경로와 인기 콘텐츠를 함께 기록합니다.
- 저장소별 숫자를 단순 합산하지 않고 각 저장소의 역할에 맞는 지표를 봅니다.

## 4주 실험

1. 1주차: 대표 저장소 README와 프로필 고정 저장소를 정리합니다.
2. 2주차: 30~60초 데모 또는 한 장짜리 사용 흐름을 게시합니다.
3. 3주차: 실제 문제 해결 사례 한 건을 Showcase에 공개합니다.
4. 4주차: 방문, Star, 다운로드 변화와 유입 경로를 비교해 다음 개선 한 가지만 선택합니다.
